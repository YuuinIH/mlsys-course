# 贡献指南

欢迎改进独立文章、修订论证、补充可信测量和公开案例，或者提出一个值得理解的系统问题。

## 贡献什么

选题应帮助读者理解 ML 系统的**资源约束、运行机制、性能证据或设计权衡**，而不是重讲完整 ML 算法、罗列工具功能、追逐技术热点，或为某项技术做宣传。

可以写概念讲解、源码走读、实验记录、架构分析、技术史或论文讨论。**不是每篇文章都需要 Lab**，也不要求写成统一结构；参考[文章写作建议](/guide/article-guide)。

## 如何标记

- **L1 / L2 / L3**：指阅读门槛，不代表文章重要性。
- **初稿 / 待验证 / 可学习**：标记内容成熟度。只有提纲的占位稿不应列为正式文章。

## 有实验的时候

只有实践确实帮助认识问题时才做实验。需要记录问题与可证伪假设、关键环境和输入、方法、原始结果摘要、混杂因素和适用边界。小规模实验、模拟与公开 trace 都可以有教学价值，但不要将其等同于真实生产经验。

允许 AI 协助代码实现与分析，不以手写代码量评价理解；AI 产出的代码、数据与结论仍需要核验。

## 提交内容

1. 在[主题地图](/topics/)中定位系统问题，阅读[课程设计](/outline)确认边界。
2. 新文章优先放 `docs/essays/<slug>.md`，不需要旧式章节编号。
3. 尽可能独立讲清问题、证据、解释和局限，并注明难度与成熟度。
4. 正文可读后更新[专题文章](/essays/)与相应[主题地图](/topics/)；只有确实改善顺序时才改[学习路径](/paths/)。
5. 检查引用、内部链接和 `pnpm docs:build`。

少而准确的贡献比大量空白章节更有价值。

# 学习路径 · Paths

Hello MLSys 以**独立问题文章**为基本单元。学习路径是从已有内容中选取阅读顺序，不是文章存储目录，也不限制作者按什么顺序写作。

## MLSys Fundamentals · 当前可走的起步路径

面向已有计算机本科基础、希望先形成系统直觉的读者：

1. **[为啥需要 MLSys？](/modules/00-systems-thinking)** · L1 · 导论。借助「星际之门」和真实 ML 请求，理解为什么模型之外还有系统问题。
2. **[规模效应：算力、能力与成本](/modules/0X-scaling)** · L2 · 扩展。认识规模化为什么不等于线性收益，以及性能与美元成本的关系。
3. **[为什么需要专门的 LLM 推理引擎？](/essays/serving-tuning/00-why-inference-engines)** · L2 · 服务。从单次前向进入多请求调度、Batching 与缓存的设计动机。
4. **[推理服务性能测量](/essays/serving-tuning/01-what-is-fast)** · L2 · 证据。学习如何区分请求延迟、吞吐、Goodput 与不同负载条件下的结果。

上述 **4 篇均为初稿**，其顺序只是一条可行路线。第二、三、四篇也可按兴趣独立阅读。**现有内容还不足以构成完整 Fundamentals 课程。**

## 完整课程希望形成怎样的认识？

以下是**未来知识覆盖的轮廓，不是现成阅读链接或承诺完成的章节**：

| 阶段 | 学习问题 | 需要逐步补充的内容 |
| --- | --- | --- |
| **I · 看见问题** | 系统为何存在，怎样认识真实性能？ | ML 工作负载、执行路径、硬件约束与测量 |
| **II · 让模型训练** | 单机训练怎样消耗资源，扩展与后训练引入什么复杂性？ | Training Step、数据供给、通信、分布式并行、Rollout |
| **III · 让模型服务** | 单次计算如何变成可服务并发请求的系统？ | 服务调度、推理加速、KV Cache、P/D 分离与状态生命周期 |
| **IV · 让平台运行** | 从本地代码到生产集群，哪些机制不可省略？ | 容器、Kubernetes 控制循环、隔离、可观测性、可靠性 |
| **V · 让工程可持续** | 为什么合理的技术方案也可能失败？ | 成本与容量、软件工程、团队责任、资源分配与组织协作 |

每个阶段都允许使用小实验、源码和案例，也允许跳过不必要的实现。课程不会为了满足这张表而提前创建空白文章。

等某个方向有足够多的可读文章，再考虑拆出训练、推理或平台专题路径。想按话题探索请看[主题地图](/topics/)；想读现有文章请看[专题文章](/essays/)。

# 推理服务调优：从能跑到好用

> 本专题持续编写中：第 0 节已有可读初稿，后续七节仍是写作提纲。

把大语言模型部署成一个 API 并不算难；难的是让它在自己的硬件和请求负载上真正好用。vLLM、SGLang 都提供了不少参数，但我们并不准备从参数列表或论文目录开始讲。这一章从实际使用时遇到的问题出发，看看哪些设置能帮忙，哪些改了也未必有用。

## 开始之前

本章默认读者对 Transformer 和大语言模型的基本工作原理有所了解。如果你还不熟悉这些概念，推荐先阅读 Datawhale 的 [Happy-LLM：从零开始的大语言模型原理与实践教程](https://github.com/datawhalechina/happy-llm)。

本章主要讨论如何使用和调优 vLLM、SGLang 等现成的推理引擎，不涉及模型内部算法的详细推导。

序小节首先交代推理引擎的诞生背景；后续小节从识别问题开始，逐步认识显存、并发、缓存、生成加速与量化，最后回到如何判断调参是否真的有效。每节只解释足以理解配置及其代价的机制；不以实现推理引擎、推导论文公式或完成固定实验模板为目标。

具体示例会选定并标注推理引擎版本；未核实前不写易过时的默认值。vLLM 与 SGLang 可以相互参照，但不强求所有小节都维护两套完整命令。

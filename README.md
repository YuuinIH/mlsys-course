# Hello MLSys

**从计算机系统的视角，理解现代机器学习如何真正运行。**

Hello MLSys 是一套持续生长的开放课程，面向具备计算机本科基础、希望理解现代 ML 系统的读者。我们关注**工作负载、执行机制、资源约束、测量证据与工程权衡**，而不是罗列 AI Infra 工具。

课程的基本单元是可独立阅读的专题文章；主题地图界定问题范围，学习路径帮助组织阅读。**有推荐学习主线，但不要求按章节编号写作或阅读。**

## 课程目录 · 五个认识阶段

| 阶段 | 核心问题 | 典型内容 |
| --- | --- | --- |
| **I · 认识系统** | 一个 ML 工作负载究竟对计算机提出了什么要求？ | 星际之门、模型执行栈、GPU / 内存 / 带宽、通用实验方法 |
| **II · 让模型训练** | 从单机训练到大规模迭代，多出来了什么系统代价？ | Training Step、数据供给、显存、分布式训练、后训练 |
| **III · 让模型服务** | 一次推理怎样成为可靠的多用户服务？ | 请求调度、Batching、推理性能与调优、P/D、KV Cache、状态生命周期 |
| **IV · 让平台运行** | 如何让系统在真实集群中持续提供服务？ | 容器、Kubernetes、资源调度、可靠性、可观测性 |
| **V · 让工程可持续** | 谁为效率、复杂度与风险付费？ | 容量与成本、软件工程、DevOps、资源分配、组织协作 |

这是**知识主线，不是已完成的五个单元**；其中的案例与工具只服务于系统问题。完整候选问题在[课程设计大纲](COURSE_OUTLINE.md)和[主题地图](docs/topics/index.md)中。

## 我们不做什么

不重讲完整的 ML 算法、操作系统或编译器课程；不编写工具安装大全、热点新闻合集、RAG 应用教程或特定技术路线的宣传材料；也不要求学生通过实现大型平台来证明学会知识。PyTorch、CUDA、Kubernetes、开源推理引擎和论文都是用来**解释某个系统问题**的材料。

文章按阅读门槛标记 **L1 Fundamentals / L2 Engineering / L3 Advanced**；实践包括实验、源码阅读、测量、案例比较与成本估算，目标是检验理解，而非交付工程量。涉及状态管理与组织协作时，也应明确设计假设和证据边界。

参与编写见[文章写作建议](docs/guide/article-guide.md)和[贡献指南](docs/guide/contributing.md)。

## 在本地运行

需要 Node.js 和 pnpm。

```bash
pnpm install
pnpm docs:dev
```

构建静态网站：`pnpm docs:build`。
